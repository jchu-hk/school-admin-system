
### 2. 深度排查 - 测试环境配置
运行第一个测试用例 `SM-001`:
- **错误现象**: 60秒超时，等待 `getByTestId('username-input')`
- **截图分析**: 页面显示 "Control UI did not start" - OpenClaw错误页面

检查Playwright配置文件 `playwright.config.ts`:
```typescript
baseURL: process.env.BASE_URL || 'https://aade13aa-91de-4793-9a07-a613f42a5cc4.dev.coze.site/school-admin/'
```

**🚨 根因发现**: 
- `baseURL` 指向了错误的Coze开发环境URL
- 实际测试服务运行在 `http://localhost:8080`
- 测试访问了错误页面，导致所有元素选择器超时

---

## ✅ 修复措施

### 修复1: Playwright配置
```diff
- baseURL: 'https://aade13aa-91de-4793-9a07-a613f42a5cc4.dev.coze.site/school-admin/'
+ baseURL: 'http://localhost:8080'
```

### 修复2: 前端data-testid统一命名
统一表单字段命名规范为 `field-{字段名}`:
```diff
- data-testid="student_id"
+ data-testid="field-student_id"

- data-testid="name_zh"
+ data-testid="field-name_zh"

- data-testid="class_id"
+ data-testid="field-class_id"
```

### 修复3: 前端重新构建部署
```bash
cd school-admin-frontend && npm run build
docker cp dist/. school-admin-frontend:/usr/share/nginx/html/
docker exec school-admin-frontend nginx -s reload
```

## 🎯 根因总结

### 问题本质
**这不是页面性能问题，而是测试环境配置错误导致的"假超时"**

测试用例访问的是完全不同的URL（Coze开发环境），而不是本地测试服务。因此：
- 页面内容与预期完全不同
- 所有元素选择器都无法找到目标
- 看起来像是"加载超时"，实际是"页面不存在"

### 错误链路
```
测试启动 → baseURL指向错误URL → 访问错误页面 → 元素不存在 → 等待超时 → 测试失败
```

### 影响范围
- **全部35个测试用例**都受此影响
- **并非只有CRUD用例**失败
- 修复配置后，**全部测试应能正常运行**
