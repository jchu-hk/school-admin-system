## 🎯 核心原则

1. **CHECKER全流程参与** - Requirement/UI/Code/QA/Deploy每个环节都要审核
2. **质量第一** - 不追求速度，追求质量
3. **透明管理** - 所有状态在GitHub可见
4. **流程驱动** - 遵循既定流程，不跳过步骤

## 📊 标准工作流程

### 新功能开发完整流程

```
阶段1: 需求
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. PM 创建Issue
2. REQ 撰写需求文档
3. CHECKER审核需求 ← 【必须！】
   ✅ 通过 → 进入设计
   ❌ 不通过 → 返回整改

阶段2: UI设计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. UI 设计师完成UI设计
5. CHECKER审核UI ← 【必须！】
   ✅ 通过 → 进入系统设计
   ❌ 不通过 → 返回整改

阶段3: 系统设计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. ARCH 完成API/架构设计
7. CHECKER审核系统设计 ← 【必须！】
   ✅ 通过 → 进入开发
   ❌ 不通过 → 返回整改

阶段4: 开发
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
8. DEV 开发代码
9. DEV 创建PR
10. CHECKER审核代码 ← 【必须！】
    ✅ 通过 → 进入测试
    ❌ 不通过 → DEV整改

阶段5: QA测试
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
11. QA 执行测试
12. QA 撰写测试报告
13. CHECKER审核QA报告 ← 【必须！】
    ✅ 通过 → 进入部署
    ❌ 不通过 → QA重新测试

阶段6: 部署
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
14. DEVOPS 部署
15. CHECKER部署验收 ← 【必须！】
    ✅ 通过 → 上线
    ❌ 不通过 → DEVOPS修复

阶段7: 上线
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
16. PM 合并PR
17. DEVOPS 生产部署
18. CHECKER最终验收
19. PM 关闭Issue
```

## 📋 CHECKER审核检查清单

### 1️⃣ Requirement 需求审核

| 检查项 | 标准 | 通过条件 |
|--------|------|---------|
| 需求完整性 | 覆盖所有场景 | 无遗漏 |
| 验收标准 | 可量化、可测试 | ≥3条 |
| 业务价值 | 符合实际 | PM确认 |
| 依赖关系 | 已识别 | 无黑盒 |

**评分**: ≥70% → ✅ 通过

---

### 2️⃣ UI Design 设计审核

| 检查项 | 标准 |
|--------|------|
| 用户体验 | 操作步骤 ≤ 5步 |
| 响应式 | 320px-1920px |
| 一致性 | 风格统一 |
| 可访问性 | WCAG标准 |

**评分**: ≥40/50 → ✅ 通过

---

### 3️⃣ System Design 系统设计审核

| 检查项 | 标准 |
|--------|------|
| API设计 | RESTful规范 |
| 架构 | 模块化、扩展性 |
| 安全 | 符合规范 |
| 性能 | 满足SLA |

**评分**: ≥40/50 → ✅ 通过

---

### 4️⃣ Code 代码审核

| 维度 | 权重 |
|------|------|
| 代码质量 | 20% |
| 安全性 | 25% |
| 性能 | 20% |
| 测试 | 15% |
| API设计 | 20% |

**评分**: ≥40/50 → ✅ 通过

---

### 5️⃣ QA 验收审核

| 检查项 | 标准 |
|--------|------|
| 测试用例覆盖率 | ≥80% |
| 功能测试 | 全部通过 |
| 集成测试 | 全部通过 |
| 回归测试 | 全部通过 |
| 边界测试 | 已覆盖 |

**评分**: ≥80% → ✅ 通过

---

### 6️⃣ Deploy 部署验收

| 检查项 | 标准 |
|--------|------|
| 构建 | 成功，无警告 |
| 容器 | 健康运行 |

```
    ↓          ↓         ↓            ↓       ↓       ↓
  ✅/❌      ✅/❌       ✅/❌         ✅/❌    ✅/❌    ✅/❌
   ↓         ↓          ↓             ↓       ↓       ↓
 通过       通过        通过           通过    通过     完成
   ↓         ↓          ↓             ↓       ↓       ↓

```
