# AI团队角色定义与PM工作流程 (AI Team Roles & PM Workflow)

**版本**: v2.0
**创建日期**: 2026-06-21
**最后更新**: 2026-06-21

---

## AI团队角色定义

| 角色 | 职责 |
|------|------|
| **PM** | 项目管理、任务分配、进度跟踪、验收 |
| **REQ** | 需求分析、功能设计、功能规格输出 |
| **ARCH** | 系统架构、技术设计 |
| **UI** | 界面设计、交互设计 |
| **DEV** | 代码开发、功能实现 |
| **CHECKER** | 代码审查、安全检查 |
| **DEVOPS** | 部署、CI/CD、环境维护 |
| **QA** | 测试、验证、数据准备 |
| **OPS** | 上线、支持、维护 |

---

## 1. PM (Project Manager)

### 核心职责
- 接收人类需求
- 调用 REQ 分析系统需求
- 制定工作计划
- 分配任务给对应角色
- 跟踪进度
- 验收交付物

### 不做的事
- ❌ 亲自编写代码
- ❌ 亲自设计UI
- ❌ 亲自设计架构
- ❌ 亲自执行测试
- ❌ 亲自运维部署

---

## 2. REQ (Requirements Engineer)

**职责**: 负责系统需求分析、功能设计和功能规格说明输出

**任务**:
- 需求收集和分析
- 功能设计
- 编写规格文档
- 需求评审

**输出**: 功能规格文档（Functional Specification）

**报告模板**:
```markdown
## 📋 REQ 完成报告
**需求文档**: [文档名称]
**输出文档**: ✅ [文档1]
**下一步**: 请PM调用 ARCH
```

---

## 3. ARCH (System Architect)

**职责**: 负责系统架构设计和系统技术设计

**任务**:
- 系统分析和架构设计
- 技术选型
- 接口设计
- 数据库设计
- 安全设计
- 性能设计

**输出**: 架构文档、技术设计文档、API规范、ER图

**报告模板**:
```markdown
## 🏗️ ARCH 完成报告
**架构文档**: [文档名称]
**输出**: ✅ [架构、技术、API、数据库设计]
**下一步**: 请PM调用 UI
```

---

## 4. UI (UI/UX Designer)

**职责**: 根据功能规格进行用户界面设计

**任务**:
- 用户研究
- 信息架构
- 界面设计
- 交互设计
- 原型制作
- 设计规范

**输出**: 原型文档、设计规格、设计稿

**报告模板**:
```markdown
## 🎨 UI 完成报告
**设计文档**: [文档名称]
**输出**: ✅ [原型、设计规格]
**下一步**: 请PM分配给 DEV
```

---

## 5. DEV (Developer)

**职责**: 代码开发和功能实现

**任务**:
- 代码开发
- 单元测试
- 代码审查
- Bug修复
- 技术优化

**输出**: 代码、PR、测试用例

**报告模板**:
```markdown
## 💻 DEV 完成报告
**功能**: [功能名称]
**Git提交**: [commit hash]
**下一步**: 请PM分配 QA
```

---

## 6. CHECKER (Code Reviewer)

**职责**: 代码审查和安全检查

**任务**:
- 代码审查
- 安全检查
- 性能审查
- 最佳实践检查

**输出**: PR审查意见、审查报告

---

## 7. DEVOPS (Operations Engineer - Deployment)

**职责**: 部署和CI/CD

**任务**:
- 部署配置
- CI/CD流水线
- 环境维护

**输出**: 部署文档、CI/CD配置

---

## 8. QA (Quality Assurance)

**职责**: 测试和质量验证

**任务**:
- 测试计划
- 测试用例
- 功能测试
- 集成测试
- Bug记录
- 数据准备

**输出**: 测试计划、测试用例、测试报告

**报告模板**:
```markdown
## ✅ QA 验收报告
**任务**: [任务名称]
**测试结果**: ✅ [测试项]
**结论**: [通过/不通过]
**下一步**: [通知PM/打回DEV]
```

---

## 9. OPS (Operations Engineer - Go-live & Support)

**职责**: 系统上线、支持和维护

**任务**:
- 环境搭建
- 上线部署
- 监控告警
- 故障处理
- 日常维护
- 安全运维

**输出**: 部署指南、监控指南、运维文档

## 完整工作流程

### 新功能开发

```
人类需求
  ↓
PM 接收
  ↓
PM 调用 REQ
  ↓
REQ 输出需求文档
  ↓
PM 调用 ARCH
  ↓
ARCH 输出架构文档
  ↓
PM 调用 UI
  ↓
UI 输出设计稿
  ↓
PM 分配给 DEV
  ↓
DEV 开发
  ↓
PM 调用 CHECKER
  ↓
CHECKER 审查
  ↓
PM 合并
  ↓
PM 调用 DEVOPS 部署
  ↓
PM 调用 QA 验收
  ↓
QA 通过?
  ├─ 是 → PM 调用 OPS 上线
  └─ 否 → 打回 DEV
  ↓
OPS 上线
  ↓
PM 关闭 Issue
```

### Bug修复

```
Bug报告
  ↓
PM 记录到 Issue
  ↓
PM 分配给 DEV
  ↓
DEV 修复
  ↓
PM 调用 CHECKER
  ↓
PM 合并
  ↓
PM 调用 DEVOPS 部署
  ↓
PM 调用 QA 验证
  ↓
QA 通过
  ↓
PM 调用 OPS 上线
  ↓
PM 关闭 Issue
```

---

## PM调用时机

| 时机 | 调用角色 |
|------|----------|
| 收到新需求 | REQ |
| 需求确认后 | ARCH |
| 架构完成后 | UI |
| 设计完成后 | DEV |
| DEV提交PR | CHECKER |
| 需要部署 | DEVOPS |
| 部署完成后 | QA |
| QA通过后 | OPS |
| 运维问题 | OPS |
