## 🔴 问题分析

### 问题1: 数据源集成完全缺失 (P0)

**现状**: 
- 没有eClass集成服务
- 没有门禁刷卡机集成
- 没有人脸识别闸机集成
- 没有自动同步机制

**影响**:
- 每天几百到一千学生的出勤数据必须手动录入
- 校务同工工作量巨大
- 数据录入容易出错
- 无法实现"每日晨检仪表板"的实时性

### 问题2: 批量导入效率问题 (P1)

**现状**:
- 批量录入功能存在，但需要手动准备数据
- 没有Excel/CSV导入功能
- 没有模板下载

**影响**:
- 校务同工需要手动填写JSON格式数据
- 不符合实际操作习惯

### 问题3: 数据源冲突处理缺失 (P1)

**现状**:
- 规格定义了冲突场景（eClass vs 门禁数据不一致）
- 没有实现冲突检测
- 没有实现冲突解决机制

**影响**:
- 当多个数据源数据不一致时，无法自动处理
- 需要人工逐一核实

---

## 📊 场景模拟

### 场景: 校务同工处理每日出勤

**预期流程**:
```
1. 系统自动从eClass/门禁拉取数据
2. 数据自动同步到系统
3. 校务同工查看仪表板
4. 处理异常情况
```

**实际流程**:
```
1. 校务同工手动收集各班出勤数据
2. 手动录入到系统（逐班、逐学生）
3. 需要处理几百到一千条记录
4. 极其耗时且容易出错
```

## 🎯 整改建议

### P0 - 必须立即实现

#### 1. Excel/CSV批量导入功能

**优先级**: P0
**工作量**: 2-3天

```
功能要求:
1. 提供Excel模板下载
2. 支持Excel/CSV上传
3. 数据验证和预览
4. 批量导入确认
5. 错误报告生成

API:
POST /api/attendance/import/preview
POST /api/attendance/import
GET /api/attendance/import/template
```

#### 2. eClass API集成服务

**优先级**: P0
**工作量**: 3-5天

```
功能要求:
1. eClass API连接配置
2. 定时同步任务（每天早上6:00）
3. 数据格式转换
4. 同步状态监控
5. 失败重试机制

配置:
ECLASS_API_URL=
ECLASS_API_KEY=
ECLASS_SYNC_CRON=0 6 * * *
```

### P1 - 短期实现

#### 3. 门禁刷卡机集成

**优先级**: P1
**工作量**: 3-5天

```
功能要求:
1. WebSocket实时接收
2. 设备状态监控
3. 数据格式标准化
```

#### 4. 数据源冲突处理

**优先级**: P1
**工作量**: 2天

```
功能要求:

```
