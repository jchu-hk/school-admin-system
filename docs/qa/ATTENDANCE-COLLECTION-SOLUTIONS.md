# 📋 出勤数据收集方案分析

**需求来源**: 用户反馈 (2026-06-18)
**业务场景**: 每天几百到一千学生出勤数据收集
**约束**: 手动输入数据不可行

---

## 🎯 问题定义

**核心问题**: 如何高效收集每天几百到一千学生的出勤数据？

**现状**:
- eClass/门禁集成未实现
- 手动逐条录入不可行
- Excel导入只是部分解决

---

## 📊 解决方案对比

### 方案A: 自动数据源集成

| 项目 | 说明 |
|------|------|
| **描述** | 对接eClass API、门禁刷卡机、人脸闸机 |
| **优点** | 完全自动化，无需人工干预 |
| **缺点** | 依赖学校现有系统，实施周期长 |
| **工作量** | 5-10天 |
| **适用性** | 有eClass/门禁的学校 |

### 方案B: Excel/CSV批量导入

| 项目 | 说明 |
|------|------|
| **描述** | 导入预先准备的Excel文件 |
| **优点** | 批量处理，减少录入次数 |
| **缺点** | 仍需人工准备Excel，不是实时 |
| **工作量** | 2-3天 |
| **适用性** | 有专人准备数据的学校 |

### 方案C: 手机APP扫码签到

| 项目 | 说明 |
|------|------|
| **描述** | 教师/学生用手机APP扫描二维码签到 |
| **优点** | 实时、便捷、无需额外设备 |
| **缺点** | 需要开发手机APP |
| **工作量** | 5-7天 |
| **适用性** | 所有学校 |

### 方案D: 教师班级打卡

| 项目 | 说明 |
|------|------|
| **描述** | 教师在本班扫描学生证/二维码完成点名 |
| **优点** | 教师可控，数据准确 |
| **缺点** | 需要教师配合 |
| **工作量** | 3-5天 |
| **适用性** | 所有学校 |

### 方案E: 混合方案

| 项目 | 说明 |
|------|------|
| **描述** | 结合自动同步 + 扫码签到 + 手动补充 |
| **优点** | 灵活性高，适应多种场景 |
| **缺点** | 实现复杂 |
| **工作量** | 7-14天 |
| **适用性** | 所有学校 |

---

## 🎯 推荐方案

### 短期方案 (P0)

**方案D: 教师班级打卡**

```
流程:
1. 教师打开手机页面/小程序
2. 选择本班
3. 扫描学生证上的二维码
4. 或手动选择学生标记出勤状态
5. 批量提交

优点:
- 无需额外设备
- 实时数据
- 教师可控
- 可离线操作（缓存后同步）
```

### 中期方案 (P1)

**方案A + C: 自动同步 + 扫码补充**

```
流程:
1. 系统自动从eClass/门禁获取数据
2. 教师用APP补充漏签学生
3. 系统合并数据
```

## 📝 功能需求 (方案D: 教师班级打卡)

### 移动端页面

| 功能 | 说明 |
|------|------|
| 班级选择 | 教师选择今日要签到的班级 |
| 学生列表 | 显示本班所有学生 |
| 扫码签到 | 扫描学生证二维码 |
| 手动标记 | 点击学生姓名标记状态 |
| 批量提交 | 一次提交全班出勤 |
| 离线缓存 | 无网络时缓存数据，联网后同步 |

### API端点

| 端点 | 说明 |
|------|------|
| GET /api/attendance/mobile/classes | 获取教师负责班级 |
| GET /api/attendance/mobile/class/:id/students | 获取班级学生列表 |
| POST /api/attendance/mobile/scan | 扫码签到 |
| POST /api/attendance/mobile/batch | 批量提交 |

## 💡 其他考虑

### 学生证二维码

- 可打印贴在学生证上
- 内容: `STUDENT:{student_id}:{name}`
- 可批量生成打印

### 班级二维码

- 每个班级一个固定二维码
- 学生扫码自动关联班级
- 适合高年级学生自主签到
